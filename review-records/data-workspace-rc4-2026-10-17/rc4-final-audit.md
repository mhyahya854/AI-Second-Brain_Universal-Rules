## 6. Technical research

The October 17 research record and the October 18 independent Red reports used primary JSON/Base64/JCS RFCs, Git object documentation, SQLite atomic-commit/WAL/network guidance, Linux rename/fsync/inotify, Android and Apple storage/uninstall guidance, and S3 consistency documentation. Material conclusions: JSON value equivalence does not preserve original bytes; Base64 is reversible encoding with approximately 4/3 expansion, not encryption; Git stores content objects in addition to hashes; one-file/object atomicity does not imply a durable multi-artifact workspace transaction; watchers can miss changes; mobile app-private files/keys can disappear on deletion; and standard SQLite WAL is not a general multi-host network-filesystem database protocol.

For 100 decimal GB of binary originals, originals plus two separately encoded complete payload layers approach 366.7 GB before metadata, nested encoding, temporary generations, history, backups, compression or filesystem effects. This is an assumption-bound logical illustration, not a platform benchmark. Streaming can limit some memory use but cannot remove total I/O and may still allocate an enormous token. No save algorithm, physical optimization, runtime guarantee or model capability was certified by this research.
