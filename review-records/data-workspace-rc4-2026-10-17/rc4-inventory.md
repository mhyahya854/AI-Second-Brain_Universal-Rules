## Conflict and preservation ledger

1. **INFO-1 / SURVIVE-1 format freedom:** Current explicit phrases “universal filenames are not required” and “no one format is universally mandatory” cannot coexist unqualified with new literal JSON policy. Replace those permissions only in relevant retained-data scope, retain alternate operational engines and platform adaptations, and cite new controlling rules.
2. **INFO-2 logical entry freedom:** Preserve equivalent APIs/platform arrangements only with explicit mapping to preferred discovery documents and mandatory full JSON recovery. Do not let “equivalent” mean opaque service-only records.
3. **LIFE-3 colocation:** Existing executable/data colocation remains valid only when lifecycle contracts preserve retained information; explicitly link new workspace separation so colocation never means disposable installation-only preservation.
4. **INFO-3 duplication:** Avoid unnecessary duplication for organizational views; owner-required literal JSON is intentional recovery duplication with explicit authority/lifecycle, not prohibited canonical view copying.
5. **DATA-1 authority:** First-class recovery representations are not two sovereign conflicting authorities. App Plan determines committed revision and admissible recovery; schema-valid, hash-matching or newer contents can still be wrong.
6. **DATA-2 regeneration:** Preserve exact original bytes and needed metadata; JSON envelope reproducibility is not permission to regenerate nondeterministic user artifacts. Derived index exclusion requires explicit classification and preserved rebuild dependencies.
7. **DATA-3/4/5:** Keep original/derivative lineage and notes overlays; portable bytes/names and locale/time semantics; times alone never resolve conflicts.
8. **STORE/CON/OUT/AUDIT/OPS/RETRY:** State invariants without choosing ack-after-both versus durable-pending, one atomic multi-file mechanism, one retry budget or file replacement algorithm. Staging/journal/durable evidence must not be mistaken for final complete recovery representation. Resource preflight is not future-space guarantee.
9. **PRIV-1/SEC-2:** Complete retention covers authorized retained scope, not perpetually erased data or plain credentials. Duplicate layers/history/backups must honor deletion and secret protection. Record recoverable encrypted values and independently recoverable keys as appropriate; never package publicly readable usable secrets to satisfy completeness.
10. **Self-reference/history:** Scope classification must prevent current JSON containing its entire self/current snapshot lineage forever while preserving retained historical payload information and ordinary content. History packaging, keys, manifests and serialization dependencies must be explicit; a references-only “history” exception cannot silently omit retained user history from the global contract.
11. **BACKUP protection:** Both complete current copies share errors and often failure domain. Protected history must have independent controls; ordinary credentials should not delete every generation, but legitimate erasure still needs a supported governed path.
12. **External editing/authority:** Human ownership permits deliberate direct editing but not automatic trusted adoption; AI must use permission-enforced approved operations. Editable SKILL.md is data until independently trusted, not elevated authorization.
13. **NAS and topology:** SYNC-3's existing enabled-NAS primary synchronization hub is settled. Keep it; distinguish hub role from universal write authority topology, which remains explicitly open. Local working copies may be scoped; do not require enormous full global file on each phone merely by inference.
14. **NOFALL:** JSON recovery layers and independent recovery tools have genuine recovery roles. Failed save cannot create empty workspace or silently substitute an implementation. Recovery reports actual restored point and loss; it does not masquerade as failed capability success.
15. **Three architectures:** Runtime workspace, development Master Plan and feature-first Codebase are distinct. Menemora example is not an implemented filesystem, required feature catalog or source repo private data placement.
16. **Small models:** 1B navigation target and 4B implementation target need separate trials. Bounded context cannot omit applicable permission/retention/phase constraints. No actual trial has been run by this inventory work.
17. **Governance/provenance:** Update current RC4 authority/status without rewriting October 14/15 historical statements as current evidence. Keep frozen rc3 bytes and evidence refs unchanged, and insert current precise historical linkage. External receipts preserve candidate exact bytes without self-referential hashes.
18. **Testing proportionate and finite:** New demanding fixtures are mandatory where relevant; avoid universal irrelevant tests/stateless machinery and don't weaken fixed acceptance criteria. Valid material limitations remain honest blockers rather than false passes.
