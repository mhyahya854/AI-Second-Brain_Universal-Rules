|---|---|
| C01 — Literal reconstruction | A JSON original with CRLF, unusual escapes, duplicate keys or a high-precision number is parsed and reserialized; a hash-only media record is claimed recoverable. JSON-1 requires “a reversible original-byte representation separately from any parsed interpretation” and prohibits pointers/hashes alone. Parser limits/duplicates/numeric semantics are explicit. **NOT AN ISSUE; high confidence.** |
| C02 — Recursive self-inclusion | Global JSON includes its own bytes and digest, then embeds history snapshots containing itself. JSON-3 requires “a mathematically finite serialization and reconstruction policy,” separate generated-envelope targets and explicit hash domains; it prohibits recursive snapshots. This permits finite serialization without abandoning ordinary retained payloads. **NOT AN ISSUE; high confidence.** |
| C03 — Global serialization cost | A 100 GB archive fits on a 128 GB device only because Base64, staging or whole-global writes were omitted from estimates. WORKSPACE-TEST-2 requires capacity, amplification, lifetime and peak-resource accounting; “None ... excuses complete payloads.” The 11/3 illustration is conditional and correctly computed for two once-encoded layers. **NOT AN ISSUE; high confidence.** |
| C04 — Simultaneous updates | Two writers read the same revision and overwrite each other after separate hash checks. CON-1 says version checks “MUST be coupled to transitions”; JSON-4 requires enforced authority/current-state coordination. A convention or timestamp cannot be the concurrency proof. **NOT AN ISSUE; high confidence.** |
| C05 — Valid-but-incorrect copies | Both JSONs parse and agree on a wrong transcript, so reconciliation labels them verified factual truth. JSON-4 says “equal copies alone does not establish legitimacy, factual correctness or successful commit”; its recovery scenarios include valid-but-wrong copies. **NOT AN ISSUE; high confidence.** |
| C06 — Propagated AI errors | A permitted bulk AI edit makes the same semantic mistake in originals, individual JSON and global JSON. REV-2 says “Equal current copies cannot undo an incorrect change already propagated to both,” requiring independent earlier points; AI-3/REV-1 preserve limits and operation evidence. Recovery may be incomplete under declared retention, not guaranteed perfect undo. **NOT AN ISSUE; high confidence.** |
| C07 — Protected history deletion | Normal editing credentials remove every historical generation. REV-2 requires meaningful separation and independently protected recovery points; normal/AI editing credentials “SHOULD NOT automatically have unrestricted deletion authority.” The SHOULD does not erase the independent-protection outcome or AUTH/SEC requirements, and justified residual risk cannot be called immunity. **NOT AN ISSUE; high confidence.** |
| C08 — Legitimate external edit | A user edits an original while the app is stopped; older JSON silently restores over it on startup. REV-1 says “An older JSON MUST NOT silently overwrite the user's changed original”; comparison, supported adoption and conflict handling are required. **NOT AN ISSUE; high confidence.** |
| C09 — Cloud/NAS conflict | A cloud folder exposes the new global but old individual JSON; a watcher misses a remote update, and a client assumes this is one atomic commit. JSON-4 disallows assumptions of atomic cloud publication; REV-1 requires reconciliation before adoption/destructive overwrite; CON-1 and OUT-1 govern races and unknown outcomes. **NOT AN ISSUE; high confidence.** |
| C10 — Mobile uninstall | A picker exposes app-private files and the product claims survival without testing deletion. | C12 — False recovery guarantees | Both current copies and protected history are lost, or keys/readers disappear, but a repair tool claims restored health. | C13 — Hash misuse | An attacker changes payload plus colocated manifest, or a self-digest includes itself, and verification claims authenticated history. | C15 — No-fallback interactions | A stale global is presented as successful saving because individual JSON succeeded; conversely restoration from one surviving representation is prohibited as fallback. | X01 — Raw → scan → sync → restore | A malicious file passes a false-negative scan, syncs through a NAS, enters JSON/history, and is later restored as trusted executable content.
