### 31.2. DEV-2 — Refine the idea before implementation

**Type:** ECOSYSTEM POLICY | **Origin:** USER POLICY | **Applies:** new applications before implementation begins

Implementation MUST NOT begin merely because an initial idea exists. Before implementation code is changed, the idea MUST be interrogated and refined into a coherent product definition addressing the problem, users, long-term role, owned/preserved information, offline capabilities, multi-device needs, NAS behavior, desktop/mobile/web scope, Hermes/AI role, privacy/security expectations, user configuration, expected lifetime, migration/portability needs, and major failure scenarios where applicable. Record non-applicability rather than inventing unnecessary features. Brainstorming MUST NOT silently become implementation. Planning then proceeds through research, specification, and the [Plan Freeze Gate](../7-%20Attacking%20and%20Freezing%20the%20Master%20Plan/710-%20Freezing%20the%20Approved%20Master%20Plan.md#dev-5).

Substantial product refinement MUST include actual value/differentiation under [DEV-18](105-%20Defining%20Goals%20and%20Success%20Criteria.md#dev-18) before architecture freeze; private/internal fit does not require a commercial moat.

The mandatory ordered workflow, including initial owner review before dedicated source discovery and final technology selection, is specified in [PLAN-1](102-%20Identifying%20the%20Actual%20Problem.md#plan-1).
